## CONFIGMAP AWS-AUTH FOR IAM USER (CONSOLE, SA)
Requirement:
1. CM has to have mapAccounts = "####". Although this gives a bug in control plane reading
2. CM has to have rolearn under mapGroups:
- groups:
  - system:bootstrappers
  - system:masters
  rolearn: arn:aws:iam::682331604648:role/project-mgmt-rancher-sts_role
  username: tuong-ngo  

3. The role with rolearn reference in step 2 above, i.e, arn:aws:iam::682331604648:role/project-mgmt-rancher-sts_role
    has to have trust relationship (sts) as below:
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "",
            "Effect": "Allow",
            "Principal": {
                "AWS": [
                    "arn:aws:iam::682331604648:user/tuong.ngo@bylight.com",
                    "arn:aws:iam::682331604648:user/bl-service-account-1"
                ]
            },
            "Action": "sts:AssumeRole"
        }
    ]
}

## ACCESS FOR K8S USERS TO WORK WITH AWS RESOURCE REQUIREMENTS
1. Cluster created
2. OIDC (authentication layer) installed after cluster creation for k8s sa to authenticate against
3. Role contains policies of various component such as vpc-cni, aws-load-balancer, aws-acm, cluster-autoscaler, ebscsi, cloudwatch
4. The same role has to have the below trust relationship (sts) where 87FE42E2F4258886AAD287E4F42B393B is the ID generated by OIDC service after creation of step 2 above:
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "",
            "Effect": "Allow",
            "Principal": {
                "Federated": "arn:aws:iam::682331604648:oidc-provider/oidc.eks.us-east-2.amazonaws.com/id/87FE42E2F4258886AAD287E4F42B393B"
            },
            "Action": "sts:AssumeRoleWithWebIdentity",
            "Condition": {
                "StringLike": {
                    "oidc.eks.us-east-2.amazonaws.com/id/87FE42E2F4258886AAD287E4F42B393B:aud": "sts.amazonaws.com",
                    "oidc.eks.us-east-2.amazonaws.com/id/87FE42E2F4258886AAD287E4F42B393B:sub": "system:serviceaccount:*:*"
                }
            }
        }
    ]
}


STEP TO RUN
#### Cluster and Node Group Creation ###
- vpc
- iam-roles
- kms
- addon/cloudwatchlog   # This will create logging for the cluster
- cluster  # This will produce the oidc for services needed such as cni, eni, ebs, ... to access and join
- local-exec   ### Must run after cluster creation and prior to any roles needed kubernetes providers authentication
- configmap # Must create prior to the creation of NG. This will allow the NG to use correct rolearn mapping to the service account system:node:{{EC2PrivateDNSName}} in the node to join the cluster
- sg  # Add custom ports rule here to be applied to worker nodes. The pods inherit the rule from here too.
- managed_ng  # Created LT and create the managed node group to join them to the cluster.
